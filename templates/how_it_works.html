▦ HOW IT WORKS

A plain-English guide to the algorithm, the engine, and the design behind the Tetris Solver.

The Big Picture

The Tetris Solver is not a human playing Tetris. It is a program that looks at a board, knows every piece that is coming next, and thinks ahead to find the exact sequence of moves that will clear a target number of lines — before a single piece has even dropped.

Think of it like a GPS. You tell it your destination (clear 8 lines) and it maps out the entire route (drop piece 1 here, piece 2 there…) before you even leave the driveway. If a road is blocked it picks a different route — it never gets lost or panics mid-journey.

The solver takes three inputs: the starting board, the sequence of pieces that will arrive, and the goal (how many lines to clear). It outputs either a complete list of winning moves, or a verdict of "not solvable" if no path to the goal exists within the piece sequence.

Why Is This Hard?

A standard Tetris board is 20 rows tall and 10 columns wide. Each piece can be rotated (up to 4 ways) and placed in multiple columns. With 40 pieces in a sequence, the number of possible game paths is astronomically large — larger than the number of atoms in the observable universe if you tried every combination naively.

The key challenge is figuring out which paths are worth exploring and which can be discarded immediately. A bad strategy here means waiting minutes for an answer; a good strategy means getting it in seconds.

The Solver: Beam Search

The solver uses a technique called beam search. Instead of chasing one sequence of moves all the way to the end (and backtracking if it fails), it maintains a collection of the most promising board states at every step — like keeping a shortlist of the best candidates rather than betting everything on one.

  1. Start with the initial board. This is the only state in the beam at the beginning.
  2. Try every possible placement of the next piece. For each state currently in the beam, the solver tests every rotation of the incoming piece at every valid column — nothing is skipped. This typically generates hundreds of new candidate boards.
  3. Score each candidate board. Every resulting board is given a score based on how "good" it looks (see the Scoring section below). Higher is better.
  4. Keep only the top N. All candidates are ranked by score and only the best ones survive into the next round. The number kept is the beam width. The rest are discarded.
  5. Repeat for the next piece. The surviving states each get expanded with every placement of the next piece, scored again, and trimmed back to the beam width. This continues until the goal is reached or the sequence runs out.
  6. Return the winning path. The moment any placement reaches or exceeds the goal line count, the solver immediately returns the full sequence of moves that led there.

Why a Fixed Beam Width Is a Bad Idea

Beam search works — but choosing a single fixed beam width creates an unavoidable tension between speed and reliability. Here is why:

  • Too narrow (e.g. width = 1): the solver only ever tracks one board state. It is extremely fast, but it has exactly one shot at finding the right path. If the heuristic scores a misleading-looking move as the best option at step 3, and the winning path actually required that move, it will never recover — there is no fallback. On easy games it gets lucky often; on harder ones it misses many solutions entirely.
  • Too wide (e.g. width = 200): the solver tracks 200 board states in parallel at every step. It is very unlikely to miss a solution, but it pays a heavy cost even on games where the very first candidate was already winning. Every piece triggers 200 × rotations × columns board evaluations — roughly 4,000 per piece, 70,000+ evaluations for a 40-piece sequence. That translates to about 2 seconds per game, which is fine for one game but painful at scale.
With a fixed width of 200, running 100 games took roughly 194 seconds. With a fixed width of 1, many of those games would have been missed entirely. Neither extreme is acceptable.

The fundamental problem is that a fixed beam width assumes every game is equally hard. In practice, most games are easy — the heuristic finds a winning path immediately with very little search — and a small handful are genuinely tricky and need a wider search. Treating all games identically wastes time on the easy majority.

The Solution: Adaptive (Progressive) Beam Search

The actual solver uses a smarter strategy: it tries the search at increasing beam widths and stops the moment it finds a solution. Hard games get the wider search they need; easy games are solved instantly at the narrowest width and never pay the cost of the wider ones.

The widths attempted in order are: 1 → 5 → 20 → 100.

  1. Try width = 1. This is just a single greedy path — the solver follows the highest-scoring option at each step with no alternatives. If it reaches the goal, return immediately. Cost: almost nothing.
  2. If that fails, try width = 5. Now five parallel paths are tracked. This catches cases where the greedy single path made one bad choice early on. Still very fast.
  3. If that fails, try width = 20, then 100. Each wider pass covers more of the search space. By the time we reach width = 100, nearly all solvable games have been found. Only genuinely unsolvable games reach this point and come back empty.
Result: 100 games solved in 2.4 seconds total (0.024s per game) at 100% win rate — an 80× speedup over a fixed width of 200, with no loss in accuracy. Most games were solved at width = 1 or 5, spending an average of only ~620 board evaluations instead of ~70,000.

How Boards Are Scored

After each piece is placed the resulting board is given a numerical score. The solver uses this score to decide which boards are worth keeping. Four factors are combined:

Factor What it measures Effect on score
Lines cleared How many complete rows were just cleared +1000 per line (dominant)
Aggregate height Total height of all 10 columns added together −51 per unit (penalised)
Holes Empty cells that are trapped below filled cells −35 per hole (penalised)
Bumpiness How uneven the top surface of the stack is −18 per unit (penalised)
In plain English: the solver strongly prefers boards that clear lines immediately, then prefers boards where the stack is short, the surface is flat, and there are no trapped gaps. A board that just cleared two lines will almost always beat one that didn't, no matter how tidy it looks.

These weights are based on well-studied Tetris AI research. The heavy bonus for line clears keeps the solver focused on its goal, while the penalties for height, holes, and bumpiness steer it toward board states that set up future clears well.

Under the Hood: The Tetris Engine

Underneath the solver is a set of fast, focused functions — the "engine" — that handle all the actual Tetris rules. These functions are completely separate from the solver logic, which makes the code easy to test and modify independently.

  • Drop: given a piece and a column, calculate exactly which row it lands on (gravity simulation).
  • Place: write the piece's cells onto the board at the landing position.
  • Clear: remove any fully filled rows and slide everything above down.
  • Valid columns: find all columns where a given piece fits without going out of bounds or overlapping existing blocks.
  • Score: compute the four-factor board score described above.

The board is stored as a grid of 0s and 1s (0 = empty, 1 = filled). Pieces are stored as small grids of the same format and are pre-loaded into memory at startup so the solver never has to convert them during search.

Generating a Game

Every game starts from a board that is already partially filled. This is generated randomly but deterministically — the same seed number always produces the same board, so results are reproducible and shareable.

  1. A random number generator is initialised with the seed value.
  2. Random pieces are dropped onto an empty board one at a time, just like a real game, until the stack reaches the desired starting height.
  3. The piece sequence for the solver is then generated using the 7-bag system — the same method used in official Tetris. Each "bag" contains exactly one of every piece type, shuffled randomly. This ensures you never wait too long for any piece. As an extra rule, two S or Z pieces are never placed back-to-back.

The 7 Tetromino Pieces

All 7 standard Tetris pieces, coloured according to the official Tetris guideline:

I — straight (4-wide) O — square T — T-shape S — S-skew Z — Z-skew J — J-shape L — L-shape

Each piece can be rotated before placement. I, S, and Z have 2 unique rotations; L, J, and T have 4; O looks the same in all rotations so it has just 1. The solver always tries every rotation for every piece.

Simulation Mode

The Simulation tab runs the solver across many different seeds at the same time, using all available CPU cores in parallel. Each game is solved independently, and the results are combined to give you a picture of how often the solver succeeds under your chosen settings.

  • Win rate — what percentage of games were solved
  • Avg evaluations — how many board positions the solver considered per game
  • Avg time — how long each game took to solve

Raising the goal (more lines to clear) or the initial height (taller starting stack) makes puzzles harder and brings the win rate down. Lowering them gives the solver more room to work and pushes the win rate up. Use simulation to find the sweet spot for your difficulty preference.
